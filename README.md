# 耐萌达人资料录入工具

粘贴微信资料 → AI 识别 → 商务确认 → 入库 → 全员可查。

零第三方依赖，只用 Node 内置模块。不装 npm 包，不用构建。

---

## 快速开始

```bash
cd naimeng-intake
node server.js
```

打开 http://localhost:5173，首次进入会引导你填「设置 → 用户设置」（姓名 + 角色）。填完就能用。

**不配模型也能跑** —— 此时使用内置的本地模拟识别，够把交互流程走通，但准确率明显低于真实模型。

## 设置

右上角 ⚙ 设置，左侧两个菜单。

### 用户设置

姓名、角色（商务 / 运营 / 仓库）、联系电话。这是这台机器上的当前操作人，**达人归属和识别留痕都记在这个身份下**，所以必须先填。

### 模型设置

仅支持 OpenAI 兼容接口，界面里改完立即生效，不用重启。

| 字段 | 说明 |
|---|---|
| 服务商名称 | 仅界面显示 |
| Base URL | 如 `https://api.deepseek.com/v1` |
| 模型名称 | 如 `deepseek-chat` |
| **接口形态** | `chat` = `/chat/completions`（绝大多数服务）；`responses` = `/responses` |
| API Key | 存在本机 `data/db.json`，留空表示不修改。可「清除 Key」回落到模拟识别 |
| 并发识别数 | 连续粘贴多个达人时同时跑几条 |
| 超时 | 长资料 + 多账号可能要 40 秒以上 |

顶部有 DeepSeek / 通义千问 / 豆包 / Kimi / 智谱 / 本地 Ollama 的一键预设，点一下自动填好 Base URL 和模型名，只需再填 Key。

填完点「测试连接」会发一条极短请求验证配置是否可用。

单条资料约 2500 输入 tokens，DeepSeek 每条成本约 ¥0.003。

> `.env` 仍然支持，作为设置的初始值。界面里填写的配置优先级更高。

## 三个功能

### 1. 录入（识别在后台跑，不用等）

**左边粘贴，右边队列**。粘贴 → 「提交识别」（或 `Ctrl+Enter`）→ **输入框立刻清空，马上粘下一位**。

识别在后台并发进行，右侧「识别队列」实时显示进度。全部跑完后，逐条点「去确认」核对入库。

这样商务的动作变成两段：先把手上几个达人的资料一口气粘完，再统一确认。单条识别要多久就不重要了。

默认并发 3 条，`.env` 里 `LLM_CONCURRENCY` 可调。服务重启时中断的任务会自动恢复重跑。

顶部九个样例按钮对应真实场景中的疑难格式，可直接点开看效果：标准模板、一址多号、UID/合作码同形、混入视频号快手号、含抖音分享口令、合作码前导零、只有 UID+地址、含宠物类别、直播定向。

**为「30 秒过完一条」做的**：
- 识别完光标自动落在第一个空字段
- `Alt+N` 在待补充与需核对字段间跳转
- 点任意字段，右侧原文自动定位高亮
- 提交不做硬阻断，只在底部提示缺什么
- 资料分几条消息发来时，右下角可继续粘贴新片段「合并识别」

**识别慢怎么办**：模型输出量是主要瓶颈。提示词里已经去掉了「原文出处」字段（由本地按值反查所在行代替），单字段输出体积降 44%，多账号资料降得更多。若仍嫌慢，可换更快的模型，或把 `LLM_CONCURRENCY` 调高让队列并行消化。

**重复怎么办**：队列会实时标出两类重复 ——

- **已入库**：库里已有记录用了同一个抖音号 / UID，会显示是谁、归属哪个商务
- **队列内重复**：同一批里把同一个达人粘了两次，两条都还没入库

标红的条目直接点「丢弃」即可，也可以用队列顶部的「一键丢弃全部重复」（队列内互为重复的会自动保留最早提交的那条）。确认页上也有「丢弃这条」按钮，不必被迫存草稿或强制覆盖。

### 2. 草稿

资料不全时先「存草稿」，之后在草稿页点「继续录入」接着填。草稿不进入达人记录。

### 3. 达人记录

商务、运营、仓库切换身份后看到的是同一张表，可按昵称 / 抖音号 / UID / 合作码 / 手机 / 地址搜索。点任意行看详情，含账号列表、收件信息、其他平台账号，以及**识别留痕**（确认人、耗时、模型与提示词版本、商务改了哪些字段）。

## 设计取向

**不追求识别精度，追求「错误商务看得见」。**

商务的二次确认是流程的固有环节，所以判断标准是：这个错误商务肉眼能不能发现？

- **能发现**（字段名认错、姓名地址切分不准）→ 商务扫一眼就改，不投入工程成本
- **发现不了** → 系统必须兜住

系统兜住的四类：

| 静默错误 | 处理 |
|---|---|
| 跨平台 ID 混入抖音字段 | LLM 隔离 + `rules.js` 二次拦截（视频号 ID 形态检测），转存到「其他平台账号」 |
| 合作码前导零丢失 | 全链路字符串，从提示词铁律到入库都禁止转数字 |
| 字段残缺被卡死 | 只有「所有账号都没有抖音号和 UID」才阻断，其余一律放行 |
| UID 与合作码填反 | 两者同为 11 位纯数字时并排展示，给一个**「两者互换」**按钮 |

另外查重按蓝图 §18.9：抖音号 / UID 精确匹配即拦截（HTTP 409），并展示已有记录的归属商务；手机号相同只做弱提示，不拦截。

## 目录结构

```
server.js          HTTP 服务、API 路由、静态文件、.env 读取
lib/db.js          数据层（JSON 文件）—— 换 Postgres 只改这一个文件
lib/agent.js       LLM 调用、系统提示词、few-shot、无 key 时的本地降级解析
lib/rules.js       确定性规则：清洗、校验、消歧、静默错误检出
public/index.html  前端（单文件，无构建）
data/db.json       数据，首次运行自动创建
.env               模型配置，自行创建
```

**分层原则**：`lib/agent.js` 只负责把非结构化文本变成候选值；校验、清洗、消歧、查重全在 `lib/rules.js` 用确定性代码做，不交给模型。这样模型换掉、提示词改了，正确性保证不受影响。

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/config` | 当前身份、模型状态、设置（key 只回传掩码）、统计 |
| PUT | `/api/settings` | 保存用户 / 模型设置 |
| POST | `/api/settings/test` | 测试模型连通性 |
| POST | `/api/jobs` | **提交识别任务，立刻返回**，后台执行 |
| GET | `/api/jobs` | 任务队列（状态、摘要、耗时、token） |
| GET | `/api/jobs/:id` | 单个任务的完整识别结果 |
| POST | `/api/jobs/:id/retry` | 失败任务重试 |
| DELETE | `/api/jobs/:id` | 移除任务 |
| POST | `/api/extract` | 同步识别，仅用于确认页里的「合并新片段」 |
| GET/POST | `/api/drafts` | 草稿列表 / 保存 |
| DELETE | `/api/drafts/:id` | 删除草稿 |
| POST | `/api/creators` | 入库。冲突返回 409，`forceIgnoreConflict` 可强制 |
| GET | `/api/creators?q=` | 记录列表，支持搜索 |
| GET | `/api/creators/:id` | 详情（含账号、其他平台、留痕） |

当前身份通过 `X-User-Id` 请求头传递。**本地工具没有真实鉴权**，云端版本再补 token。

## 数据

存在 `data/db.json`，纯文本可直接打开查看。备份就是复制这个文件。

迁移到 PostgreSQL 时只需重写 `lib/db.js`，对外导出的函数签名保持不变：

```
users            用户
creators         达人（含收件信息，一个达人一份地址）
accounts         抖音账号（creator 一对多）
other_accounts   其他平台账号（仅存档）
drafts           录入草稿
intake_logs      识别留痕
```

`accounts.uid` 与 `accounts.cooperationCode` 在 Postgres 中也必须用 `varchar`，不要用整数类型。

## 已知边界

- **本地模拟识别弱于真实模型**，只覆盖常见格式。评估识别质量请先配置 `LLM_API_KEY`。
- 没有鉴权、没有 HTTPS，仅供内网或本机使用。
- 不做地址省市区标准化（仓库在速店通手工制单，整串地址够用），只剥离配送备注。
- 不含寄样、发货、投流等状态流转 —— 这一期只做「录入 + 共享只读表」。
