# 耐萌 · 商务动作入口

粘贴微信内容 → AI 识别 → 商务确认 → 一条合作记录入库。

零第三方依赖，只用 Node 内置模块。不装 npm 包，不用构建。

---

## 快速开始

```bash
cd naimeng-intake
npm run dev        # node --watch，改代码自动重启
```

打开 `http://localhost:5173`，首次进入会引导填「设置 → 用户设置」（姓名 + 角色）。填完就能用。

**不配模型也能跑** —— 此时用内置的本地模拟识别，够把流程走通，准确率明显低于真实模型。

> 改了代码但页面没变化？多半是旧进程还占着端口。`npm run dev` 报 `EADDRINUSE` 就是这个原因，先 `taskkill /F /IM node.exe`（Windows）再起。

## 核心概念：一次合作

**叙事主体是「一次合作」，不是「一个达人」。**

```
达人 creator          稳定身份 + 归属人 + 默认收件信息
  └ 抖音账号 account   抖音号 / UID / 合作码（合作码长期不变，第二次合作自动带出）

合作 collaboration     一次合作 = 一个收件地址 + 一笔费用
  ├ 产品行 ×N          可以寄多个产品，各自数量
  ├ 履约项 ×N          每个参与账号一条：拍摄进度 + 视频口令
  └ 包裹 ×N            一次合作可以拆成多个快递单
```

同一个达人再次合作，就是**新增一条合作记录**，账号和合作码复用，不新建达人。

**为什么合作要独立于达人**：换地址、换商品、不同账号组合，只有合作级快照能记对历史。收件地址存两份 —— 达人身上那份是录入时的默认值（地址基本不变，重填很烦），合作上那份是这次实际用的快照。

**为什么履约项是账号级**：一次合作可以挂多个抖音号，但拍摄进度和视频链接必须跟具体账号对应。两个号一起寄样，可能一个已发布另一个还在拍。这正是 Excel 表达不了、系统天然能做到的地方。

## 状态由动作驱动

**界面上没有让人手选状态的下拉框。** 状态一旦能手选，就会退化成 Excel —— 填的人凭印象改，越用越不准。

| 层 | 状态 | 由什么触发 |
|---|---|---|
| 合作 | 待寄样 | 提交合作时 |
| | 已寄样 | **回填快递单号时** |
| | 已完成 | 所有需出片账号都已回传时 |
| | 已终止 | 手动（达人失联/放弃） |
| 履约项 | 待拍摄 | 合作创建时 |
| | 已催拍 | 记录回访结果时 |
| | 已发布 | **粘贴视频口令时** |
| | 本次不出片 | 手动 |

「已告知达人」是合作上的标记位，不是状态 —— 它和寄样状态正交。

## 三个入口

### 1. 录入（一个输入框，系统自己分）

左边粘贴，右边队列。输入时实时显示「识别为：建档 / 视频回传」和判断依据，判错了右上角下拉手动改。

| 输入类型 | 判定依据 | 处理 |
|---|---|---|
| 达人资料 | 含 UID / 合作码 / 手机号 | LLM 识别，**进后台队列**，输入框立刻清空可继续粘 |
| 视频口令 | 含 `v.douyin.com` + 【昵称】，且无上述三者 | **本地正则，0 延迟不调模型**，直接进确认页 |
| 发货截图 | 上传或 Ctrl+V 粘贴图片 | 视觉模型识别，**1→N**，进批量回填页 |

**关键保险**：只要出现 UID / 合作码 / 手机号，一律判为建档。因为达人资料里常夹带抖音**主页口令**（也含 `v.douyin.com` 链接），只看链接会误判。

队列每条只显示四样：类型标签、达人名、状态、操作。细节都留到确认页说。

### 1.5 发货截图批量回填

仓库把速店通/菜鸟的发货列表截图发到微信，商务直接 Ctrl+V 粘进来（或点上传区选图）。识别完在队列点「去回填」，进批量匹配页：高置信默认勾选，低置信和没匹配上的手动选，「确认回填」一次过。

**匹配为什么只能是模糊的**：截图里手机号和地址门牌都是打码的（`18*****47`、`南翔镇依仁路88弄**17号2501室`），做不了精确比对。所以：

| 信号 | 权重 | 说明 |
|---|---|---|
| 收件人姓名 | 完全一致 +50 / 包含 +35 | 有脏数据，如「于小姐联系方式」被整串当成姓名 |
| 手机首尾 | +25 / **对不上 −30** | 只剩前 2 位和后 2 位，用于消歧 |
| 地址可见片段 | 按命中比例 +0~30 | 用 `*` 切开逐段比对，**不猜被遮住的内容** |
| 商品名 | +5 | 仅佐证 —— 截图是速店通的 SKU 名，跟系统预置产品名大概率对不上 |

≥60 分且无歧义 → 高置信；≥40 分 → 低置信需确认；前两名分差 <10 分标 `ambiguous`，**不敢自动选**。已完成/已终止的合作不参与匹配，单号已存在的直接标「已回填过」。

一次发货拆多个包裹时同一收件人会出现多行，提示词里明确要求**逐行提取不合并**。

### 2. 我的待办

需要你处理的事，做完自动消失：

| 待办 | 触发 | 操作 |
|---|---|---|
| 告知物流 | 有单号但未告知 | 复制物流信息 / 标记已告知（**分两步**，避免复制了忘了发） |
| 等快递单号 | 已提交寄样但无包裹，超 3 天标逾期 | 回填快递（支持多包裹） |
| 回访催拍 | 建档满 N 天仍有账号未发布 | 记录回访结果 |
| 补全信息 | 合作没有产品行，仓库无法备货 | 打开合作补 |
| 草稿未完成 / 识别失败 | | 继续录入 / 重试 |

回访**从建档日期起算**（团队现行做法），不依赖发货时间。语义是回访不只是催拍：先问收没收到，收到了再催。

### 3. 记录查询

以合作为单位，一眼看到达人、账号、产品、快递、每个账号的视频状态。可切「我的 / 全部」，他人记录手机地址脱敏。

点开合作详情能回填快递、复制物流、记录回访、终止合作；点进达人能看合作历史、识别留痕、做归属转交。

## 确认页

覆盖层，左表单右原文，底部固定操作条。

- 识别完光标自动落在第一个空字段，`Alt+N` 在待补充 / 需核对字段间跳转
- 点任意字段，右侧原文自动定位高亮
- 资料分几条消息发来？右侧可继续粘贴新片段「合并识别」
- 命中已有达人时，主按钮是「**在该达人上发起新合作**」，不新建达人
- 「仅建档，暂不寄样」和「确认并提交寄样」分开 —— 只想先建档就不用凑齐产品和地址

### 校验按动作分级

**必填不挂在记录上，挂在动作上** —— 每个字段阻断的是真正需要它的那一步。

| 动作 | 硬阻断 |
|---|---|
| 存草稿 | 无 |
| 仅建档 | 至少一个账号有抖音号或 UID |
| 提交寄样 | 收件人 + 手机 + 地址 + 至少一个产品行 |

依据：27 条真实样本里 **4 条完全没有合作码**（其中一条一次挂 6 个账号），3 条只有 UID 没有抖音号。若把三者做成硬性必填，这些资料一条都录不进去，商务只能绕过系统。但合作码不该拦寄样 —— 发货不需要它，它该拦的是投流。

## 视频口令必须完整保存

**口令是功能载体，不是噪声。**

```
0.58 复制打开抖音，看看【某某某的作品】…… https://v.douyin.com/XXXX/ :9pm KWM:/ 01/13 z@T.Lw
```

复制**整段**打开抖音会自动跳转到视频；投流时粘贴整段，千川会自动加载素材。只存清理过的 URL，运营在千川里就加载不出来，还得回头找商务要原文 —— 视频交接就落空了。

所以 `shareToken` 逐字节保存：不 trim、不去表情、不清理尾串。尾部那串看着像垃圾的字符正是抖音识别口令的一部分。

界面上的可点击链接只是预览，**交接一律用「复制口令」按钮**。合作详情里每个已发布的履约项都有这个按钮。

昵称从【】里提取，用来自动匹配这条视频属于哪个账号的哪次合作。匹配不上（达人改过昵称）会提示手动选，不会静默失败。

## 设置

右上角 ⚙，五个菜单。

**用户设置** —— 姓名、角色、电话。这是当前操作人，**达人归属和识别留痕都记在这个身份下，归属人同时是待办接收人**，所以必须先填。

**模型设置（文本抽取）** —— 仅支持 OpenAI 兼容接口，界面里改完立即生效不用重启。

| 字段 | 说明 |
|---|---|
| Base URL | 如 `https://api.deepseek.com/v1` |
| 模型名称 | 如 `deepseek-chat` |
| **接口形态** | `chat` = `/chat/completions`（国内几家都是这个）；`responses` = `/responses` |
| API Key | 存 `data/settings.json`，留空表示不修改 |
| 并发识别数 | 连续粘多个达人时同时跑几条。触发 429 就调小 |

顶部有 DeepSeek / 通义 / 豆包 / Kimi / 智谱 / 本地 Ollama 一键预设。「测试连接」会显示实际请求的完整 URL 和失败原因（DNS、连接被拒、证书、限流分别有针对性提示）。

单条资料约 2500 输入 tokens，DeepSeek 每条成本约 ¥0.003。

**视觉模型** —— 发货截图识别用，与文本模型分开配。理由：文本高频用便宜模型，视觉低频，而且 deepseek-chat 之类不支持视觉。留空则禁用截图上传。

**寄样产品** —— 录入合作时从这里选。已被合作引用的产品删除时只停用，不影响历史（产品名在合作里是快照，改名不影响已有记录）。

**流程设置** —— 回访天数、告知达人话术模板。模板占位符 `{物流}` 会把每个包裹渲染成独立一行「承运商 单号」，多包裹时不会错位。

> `.env` 仍然支持，作为设置的初始值。界面里填的优先级更高。

## 设计取向

**不追求识别精度，追求「错误商务看得见」。**

商务的二次确认是流程的固有环节，所以判断标准是：**这个错误商务肉眼能不能发现？**

- **能发现**（字段名认错、姓名地址切分不准）→ 扫一眼就改，不投入工程成本
- **发现不了** → 系统必须兜住

系统兜住的四类：

| 静默错误 | 处理 |
|---|---|
| 跨平台 ID 混入抖音字段 | 提示词隔离 + `rules.js` 二次拦截（视频号 ID 形态检测），转存到「其他平台账号」 |
| 合作码前导零丢失 | 全链路字符串，从提示词铁律到入库都禁止转数字 |
| 字段残缺被卡死 | 校验按动作分级，见上 |
| UID 与合作码填反 | 两者同为 11 位纯数字时并排展示，给一个**「两者互换」**按钮 |

查重按蓝图 §18.9：抖音号 / UID 精确匹配即拦截（409），带出归属商务和历史合作次数；手机号相同只做弱提示。**查重永远跨商务**，否则「已归属其他商务」这条规则无法工作。**强制创建已移除** —— 与「达人归属固定、禁止重复创建」直接冲突。

## 目录结构

```
server.js          HTTP 服务、API 路由、静态文件、.env 读取
lib/db.js          数据层（JSON 文件）—— 换 Postgres 只改这一个文件
lib/agent.js       LLM 调用、系统提示词、few-shot、无 key 时的本地降级解析
lib/rules.js       确定性规则：输入路由、口令解析、校验分级、静默错误检出、待办推导
public/index.html  结构与样式
public/app.js      前端逻辑
tests/             node:test 回归，零依赖
data/db.json       业务数据（含达人 PII）
data/settings.json 配置（含 API Key）
```

**三条不可越界的规则**（代码定位未定，按「本地过渡品」和「长成云端服务」两种结局都容得下来实施）：

1. **身份只有一个入口** —— `userOf(req)`。现在读设置，将来读 token。其他地方不得出现第二种「当前用户」取法。
2. **数据访问只有一个出口** —— `lib/db.js`。现在 JSON，将来整体换 Postgres，对外函数签名不变。
3. **业务规则不碰存储** —— `lib/rules.js` 保持纯函数。

守住这三条，现在一行鉴权代码都不写，将来补鉴权也不用重写业务。

**分层原则**：`agent.js` 只负责把非结构化文本变成候选值；校验、清洗、消歧、查重全在 `rules.js` 用确定性代码做。模型换掉、提示词改了，正确性保证不受影响。

四个文件：`rules.test.js`（纯函数）、`db.test.js`（数据层 + 迁移）、`api.test.js`（HTTP 端到端）、`agent.test.js`（降级路径 + **隐私扫描**）。

## 数据

`data/db.json` 业务数据、`data/settings.json` 配置。分开存的理由：**两类数据处置方式不同 —— 业务数据要备份要迁移，密钥不能跟着走**。两个文件都在 `.gitignore`。

备份就是复制 `data/` 目录。首次用新版启动会自动跑 v1→v2 迁移（达人内嵌的收件信息拆成「达人默认值 + 合作快照」），迁移前建议先备份。

`accounts.uid` 与 `accounts.cooperationCode` 在 Postgres 中也**必须用 varchar**，不要用整数类型 —— 合作码可能以 0 开头。

## 还没做的

- **速店通 API**：手工回填。回填入口按「回填」形态设计，将来接 API 只是从手填变自动填充，界面和状态流转不改
- **投流三态**（待投流 / 投流中 / 已结束）：留字段不做界面。运营不进这个系统，**没有数据来源的状态字段比没有这个字段更糟**
- 补寄 / 换地址（蓝图 W03，待仓库进系统）
- 真实鉴权、HTTPS —— 仅供内网或本机使用
